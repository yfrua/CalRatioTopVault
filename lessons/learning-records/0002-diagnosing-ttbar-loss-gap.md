# Root Causes of the ttbar HPO Performance Regression, Modality Mask Scrambling Bug, and Resolution Established

Diagnosed why HPO trials on the ttbar dataset plateaued at Signal Region validation loss >0.50 (and Trial 0 at 0.637) while the benchmark champion run achieved 0.244. Established through controlled experimentation that the failure was not a dataset Bayes error floor, but a combination of: (1) **Modality and padding mask scrambling**: salt's `Transformer.forward` and `GlobalAttentionPooling.forward` concatenate sequences and masks assuming identical dictionary key order (`list(x.values())` and `list(pad_mask.values())`). In HPO, `update_yaml_config` wrote `configs_trial.yaml` using PyYAML's `safe_dump(sort_keys=True)`, sorting `data.variables` alphabetically (`['clusters', 'jets', 'msegs', 'tracks']`), while `init_nets` was ordered `['tracks', 'msegs', 'clusters']`. This scrambled token-to-mask alignment, applying cluster masks to track embeddings and assigning $-\infty$ attention weights to real physical tracks. (2) **Global effective batch size**: champion used 4 GPUs with per-device batch size 1200 (global batch size 4800, ~6.2k steps), whereas single-GPU trials with batch size 1000 produced 5x more updates (30k steps) with high gradient noise that destabilized adversarial scale factor balance. (3) **Metric mismatch**: normalized distance in Optuna objective vs. raw Euclidean RSS $\sqrt{\mathcal{L}_{\text{SR}}^2 + \mathcal{L}_{\text{CR}}^2}$ in checkpointing. (4) **Premature schedule-blind pruning**: pruning at 30% before adversarial scale factor engaged.

Implemented comprehensive mitigations: (1) Defensively reconstructed `pad_mask` in `CalRatioTransformer.forward` to strictly follow `for key in x`, ensuring guaranteed token-to-mask alignment regardless of dictionary ordering. (2) Passed `sort_keys=False` to `yaml.safe_dump` in `update_yaml_config`. (3) Standardized `init_nets` ordering to `['tracks', 'clusters', 'msegs']` and explicit `class_names: ["Ttbar", "Signal", "BIB"]` in `generate_params.py`. (4) Transitioned to sequential multi-GPU DDP training (`n_jobs=1`, `--trainer.devices={len(gpus)}`) with batch size 1200 ($4 \times 1200 = 4800$). (5) Aligned Optuna objective to Euclidean distance $\sqrt{\mathcal{L}_{\text{SR}}^2 + \mathcal{L}_{\text{CR}}^2}$, and coupled pruning warmup to $\max(\text{base}, \text{sf\_pct\_end})$ with 1.5 slack. (6) Added automated trial enqueueing (`hp_opt/enqueue.py`).

Empirically validated on the ongoing HPO run: Trial 0 (enqueued champion config) with the bugfix achieved **SR validation loss 0.24393** and **CR validation loss 0.00354**, perfectly matching the benchmark champion (`0.24395`) and confirming full resolution.
